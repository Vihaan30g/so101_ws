1. Overview

The SO-101 is a low-cost, open-source 6-joint robot arm (shoulder pan, shoulder lift, elbow flex, wrist flex, wrist roll and a gripper). This project turns it into a platform for learning-based manipulation.

Teaching a robot by demonstration usually needs a second, master arm that a person moves by hand, which means paying again for motors and 3D-printed parts. The aim here is to replace that master arm with computer vision, so that a camera, not a second arm full of actuators, captures the operator's motion. Once demonstrations can be recorded that way, the arm will be trained with imitation learning and reinforcement learning.

The first step, and the only one completed so far, is the control layer: a ROS 2 stack that can move the arm's gripper in Cartesian space from any input device. The future camera-based master arm only has to publish the same ROS messages that the keyboard test node publishes today.

3. What is built so far

  • Cartesian control. The gripper's position can be commanded as a velocity or as a target pose. A damped least-squares inverse-kinematics solver, built on the Pinocchio robotics library, turns Cartesian motion into joint velocities.
  • Direct wrist and gripper control. Wrist flex, wrist roll and the gripper are driven directly, outside the inverse-kinematics solver.
  • Freeze and resume. The operator can freeze the arm's translation while still adjusting the wrist and gripper, then resume without the arm jumping.
  • Safety gate. Every command passes a separate node that checks joint limits, velocity limits, stale state and invalid values before anything reaches the motors.
  • Hardware bridge. A small TCP link connects ROS 2 to the LeRobot and Feetech motor driver that talks to the real arm.
  • Live visualisation. Two models of the arm can be shown together in RViz2: the commanded pose (a semi-transparent "ghost") and the actual measured pose.
  • Keyboard input. A test node publishes exactly the messages the future camera-based device will use.

4. How it is put together

The stack keeps the ROS 2 control logic separate from the process that talks to the motors. The input device only publishes messages, so it can be swapped without touching the rest.

Nodecartesian_controller_nodeInverse kinematics: Cartesian command to joint velocities

Nodetcp_bridge_nodeSends the latest command over a local TCP link

The measured joint positions travel back the other way and feed the controller and the "actual" model in RViz2.

5. How the control works

Cartesian behaviour

Only the three large joints (shoulder_pan, shoulder_lift and elbow_flex) take part in the Cartesian solution, which controls the gripper's position. wrist_flex and wrist_roll are direct orientation inputs, and the gripper is a direct velocity input. The controller accepts two modes: velocity, and pose, which uses proportional position control with a speed limit. Commands that go stale are treated as zero, so the arm stops if the input stops.

Freeze and resume

While freeze is on, the first three joints are held still and only the wrist and gripper respond. On release in pose mode, the device target is re-aligned to where the arm actually is, so it continues from there instead of jumping to the device's current position. The safety gate enforces the freeze again independently.

Safety

Joint limits and velocity limits come from the robot's URDF and are checked by the safety gate, alongside stale-state and finite-value checks and a watchdog in the motor server. These protections do not replace a hardware emergency stop. Self-collision checking is not available yet, so the arm should be tested at low speed, supervised and clear of people and obstacles.

8. Running it

Build the workspace, then start the motor server and the ROS stack:

source /opt/ros/$ROS_DISTRO/setup.bash
colcon build --symlink-install --base-paths src
source install/setup.bash

# terminal 1: the LeRobot motor server (start this first)
python3 src/so101_bringup/scripts/lerobot_server.py

# terminal 2: the ROS 2 stack
ros2 launch so101_bringup so101_stack.launch.py

# terminal 3: keyboard control
ros2 run so101_input_keyboard keyboard_servo
KeysAction
i / k, j / l, u / oMove the gripper along X, Y and Z

This needs ROS 2, the Pinocchio library, the LeRobot SDK with its calibration for your arm, and a connected SO-101. Full details are in the repository's README.
